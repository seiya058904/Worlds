# 小说创作项目规则

## 项目性质

- 本项目只用于长期小说创作，默认使用简体中文。
- 用户提供资料与反馈；Codex 负责主要创作、结构、正文、一致性与初审。
- 不创建应用、API、数据库、脚本、依赖或服务；不网络研究，除非用户明确要求。
- 不自动 commit、push 或发布。

## 创作权限与事实优先级

- Codex 自主决定普通场景细节、次要人物、对话、过渡、小型冲突与非核心伏笔；不要为此频繁提问。
- 重大方向必须服从用户硬性资料；用户最新明确指令优先级最高。
- 冲突优先级：用户最新明确指令 → `00-project/hard-constraints.md` → 已批准基础设定与整体设计 → 正式正文 → `05-continuity/` → 其他文件 → `scratch/`。发现冲突先报告，绝不静默覆盖。

## 正文前门槛

- `status.md` 未进入 `APPROVED_TO_DRAFT`、开稿审计未通过、用户未批准整体方案、用户未明确允许开稿、或文风校准未完成时，均不得创建正式章节。

## 普通任务读取顺序

1. `00-project/status.md`
2. `00-project/hard-constraints.md`
3. 与任务直接相关的基础设定与故事计划
4. 相关文风规范
5. `05-continuity/current-state.md`、`knowledge-state.md`、`open-loops.md`
6. 当前章节之前的正文结尾

只读取必要上下文，但不得遗漏关键约束。

## 设计与写作

- 先整理用户资料，再完成结局、主要节点、全部章节大纲和文风校准；明确区分用户事实、获批 Codex 设计与候选想法。
- 正文只执行已批准路线；不得为当前章节方便而改变世界规则、人物身份动机、主线、伏笔或结局。
- 写作前确认 POV、时间、地点、目标、冲突、转折、结束状态、断章方式及不可提前透露的信息。
- 正文不含分析或说明，不重复上一章结尾，不以大段回顾开场，不用无作用场景，保持人物语言、POV、人称、时态和格式一致。

## 章节完成流程

1. 执行章节、人物、世界、时间空间物品、知识边界、文风和断章检查。
2. 修正已确认的问题。
3. 更新 `current-state.md`、`timeline.md`、`knowledge-state.md`、`open-loops.md`、`canon-log.md`、相关设定和 `status.md`。
4. 汇报修改、连续性更新、冲突、未决问题、项目阶段与下一步。

纯标点或错字修正不必更新全部连续性文件。

## 修改阶段

- 先判断是校对、润色、压缩、扩写、局部/章节重写、结构/人物/世界调整或全书修订。
- 润色不改剧情，校对不改文风；结构修改与语言修改分开。重大修改先检查后续影响；Canon 变化同步连续性记录；已否决方案不得自动重提。
