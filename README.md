# Worlds

> 私人多世界观 Markdown 备忘录：用 Git 管理世界设定、灵感与长期演化记录。

以 Markdown 为主要载体、以 Git/GitHub 负责版本历史与同步。用户把自己过去或未来随手写下的世界观、设定、灵感、人物、历史、科技、力量体系、文明、地区等原始文字交给 AI；AI 的职责是整理、规范化、分析、优化、补全和维护这些世界观，而不是替用户写小说。世界观本身就是项目的主要作品，不要求最终服务于小说、游戏或其他产品。

## 夜间阅读器

在线阅读：**[Worlds · 藏书](https://seiya058904.github.io/Worlds/)**。在线站和本地阅读器都是只读版本；世界内容继续只在 `worlds/*.md` 和 Markdown 引用的原地图中维护。

### 本地阅读

双击项目根目录的 **[启动阅读器.cmd](启动阅读器.cmd)**，浏览器会打开 `http://127.0.0.1:4175`。需要 Node.js 22.12+（推荐 24 LTS；也兼容 20.19+）；首次启动会按锁文件安装阅读器依赖，需要网络，之后日常阅读使用本地资源。

- 藏书首页包含所有 `worlds/` 下的 Markdown；宋世江湖标记为“持续迭代”，其余世界标记为“典藏”。标签只用于阅读界面。
- 点击世界进入阅读，左侧目录按原文标题分组；章节内连续滚动，底部切换上一章／下一章。目录可筛选，工具栏搜索（或 `Ctrl+K`）可检索所有世界并定位到原文。
- `Aa` 调整字号、行距与字体；阅读位置和设置保存在当前浏览器。正文中的地图可全屏查看、缩放、拖动，或恢复适配窗口。
- 每次打开启动器都会重新扫描 `worlds/`，重复启动复用已有服务时也会先同步最新内容。继续使用原编辑器修改 Markdown；保存正文、添加／移走文档或替换引用图片后，网页自动同步，并尽量保留当前小节和段落位置。断开服务时会显示离线状态，恢复后重新读取。
- 标题会自动生成目录：`# 世界名` 保留为分组与引言，`## 章节名` 是章节，`### 小节名` 及更深标题成为章内小节；增删标题后目录一起更新，无需重新构建。
- 服务仅监听本机。首次启动的窗口需保持打开，关闭窗口或按 `Ctrl+C` 停止服务。

### 在线阅读与同步

- 提交并推送到 `main` 后，GitHub Actions 使用 Node 24、锁文件和完整测试自动构建并部署到 GitHub Pages；也可以手动触发 Pages workflow。部署完成后，在线站才包含这次修改。
- 在 `worlds/` 中修改正文、增删或改名章节、新增或移走 Markdown、替换文档引用的地图，都由扫描器自动更新藏书、目录、搜索和内容版本；无需在阅读器代码中登记书名或修改章节数量。测试按当前源文件核对正文和标题完整性，不固定书籍、章节或地图的总数。新增或移走世界时仍需维护本 README 的世界索引。
- 构建与本地服务共用一份安全扫描实现。构建自动把世界 Markdown 导出为正文 JSON、内容索引 `content/manifest.json`，并原样复制文档真正引用的允许图片；生成文件只存在于 `reader/dist/`，无需人工维护第二份内容。
- 本地通过 filesystem watcher / HMR 即时更新，并每 5 秒主动扫描磁盘兜底；线上每约 30 秒检查 manifest，窗口重新获得焦点、页面重新可见或网络恢复时立即检查。线上无需 Node 服务、GitHub Token、GitHub API 或 raw 地址。
- 全局、各世界和地图 revision 由实际内容的 SHA-256 计算。索引请求使用独立的防缓存参数；只有 revision 变化的世界才重新下载和解析，地图地址带图片 revision。所有正文成功后才整体切换到新版本；网络失败继续显示当前成功版本，恢复后自动重试，也可点击“重试”。首次打开或整页刷新仍需要网络。
- 更新时先记录阅读位置，再按段落指纹、小节、章节和比例尽量恢复；章节删除时回退到最近可读章节。阅读设置及位置仍保存在当前浏览器的 localStorage。hash 地址可直接分享和刷新具体世界／小节。

世界文档和原地图仍是唯一内容来源，阅读器不修改正文。应用代码、依赖和构建产物集中在 `reader/`，依赖及构建产物不纳入 Git；在线同步读取部署产物，只有本地模式直接监听文件。

开发与验证（在 `reader/` 中运行）：

```powershell
npm ci
npm run dev
npm test
npm run build
npm run preview
```

`npm run dev` 与双击入口均使用上述本机地址。`npm run build` 完成类型验证并生成完整、可独立部署的静态站点；`npm run preview` 在 `http://127.0.0.1:4176` 验证生产模式，使用构建时的内容。资源使用相对 base，支持 Pages `/Worlds/` 子路径。应通过 HTTP 服务阅读，不能双击构建后的 HTML。

## 基本使用方式

- **一个世界 = 一个 Markdown 文件**，放在 `worlds/` 目录下。文件内部用章节组织内容，不拆分成多个文件。
- **随手记录**：不确定归属的灵感、一句话想法、还没整理的原始文字，直接写进 `INBOX.md`。先记下来，比立刻整理更重要。
- **交给 AI 整理**：把散乱便签、原始文字发给 AI，AI 会按 `AGENTS.md` 的规则整理进对应世界文件，区分正式设定与候选内容。
- **修改由 Git 保存历史**：完成一次明确修改后，只暂存本次修改的文件再提交；需要同步时推送到 GitHub。任何改动都可以从 Git 历史找回。

## INBOX.md

`INBOX.md` 是整个项目唯一允许"不整洁"的地方，相当于数字便签的临时收件箱：存放还没归类、还没整理、或不确定属于哪个世界的原始内容。内容被正式整理进对应世界后，可以从 INBOX 删除。

## 关于 Git

这个仓库本身就是私人文字备忘录。Git 用于历史版本、撤销错误修改、查看世界如何逐渐演化；GitHub 用于云端保存与多设备同步。日常编辑直接在 main 上提交即可，不需要分支或 Pull Request。

详细的 AI 协作规则见 [AGENTS.md](AGENTS.md)。
